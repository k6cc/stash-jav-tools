# tagMerge

> v1.0.0：首个版本 — 按映射库将相似名称的 tags（英文/日文/中文变体）合并为规范中文 tag

Stash 任务插件：读取插件自带的映射库 `tag_merge_map.json`，把库内名称相似的 tags 合并到规范中文目标 tag。源 tag 名称合并后保留为目标的别名，场景/标记/图库/图片上的引用由 Stash 后端统一转移，数据不丢失。

## 依赖

- Stash（使用原生 `tagsMerge` mutation，仅 `source` + `destination` 基础字段，不依赖 v0.31 新增的 `values`）

- Python 3 + `requests` 库

## 安装

1. 将整个 `tagMerge` 文件夹复制到 Stash 插件目录（通常为 Stash 数据目录下的 `plugins/`）
2. 重启 Stash，在「设置 → 插件」中确认 Tag Merge 已启用

## 使用方法

1. **首次运行前建议先备份**：Stash「设置 → 任务 → 备份」（合并会删除源 tag，虽保留别名与引用，仍建议留底）
2. 打开「设置 → 任务 → 插件任务」，运行 **Tag Merge → Merge Similar Tags**
3. 在任务日志中查看结果，每组一条：`目标 ← 合并 n 个源: 源1、源2…`

映射库当前覆盖：365 个目标 / 2285 个源名称；对当前库的全量模拟结果：合并 174 组 / 253 个源 tag（含目标自身的写法变体）、新建 14 个目标、库内 tag 由 1470 精简至 1231。

## 映射库格式

`tag_merge_map.json` 为纯 JSON，可随时手动增删改：

```json
{
  "_说明": "以 _ 开头的键会被忽略",
  "3P/4P": ["3P·4P", "3P、4P", "3p", "4P", "4p", "３P"],
  "口枷": ["ボールギャグ", "口球", "球形口塞"],
  "出轨/NTR": ["NTR", "不倫", "寝取り・寝取られ"]
}
```

- **键** = 合并目标 tag 名（目标不存在时执行中自动新建）

- **值** = 源 tag 名列表（合并进目标并保留为别名）

- 以 `_` 开头的键被忽略 — 想临时禁用某条规则，把目标名加 `_` 前缀即可

- 源名匹配为**归一化后精确匹配**：全角→半角（`３P`→`3P`）、不区分大小写、忽略全/半角空格及 `·、，/` 等分隔符；不做子串或模糊匹配

## 合并行为

调用 Stash 原生 `tagsMerge`（与官方「合并」对话框一致）：

1. 源 tag 的**场景/标记/图库/图片**等引用转移到目标（后端处理）
2. 源 tag 被删除，其名称由插件补写进目标的**别名**（幂等去重，仍可通过别名搜索）
3. 目标不存在时自动 `tagCreate` 新建

## 安全机制

- **幂等**：已合并/不存在的源自动跳过，任务可安全重复执行；二次运行只会处理新增的 tags

- **防链式**：某组的目标名不会成为其他组的源，避免 A→B、B→C 连环合并

- **无删除操作**：只做合并，刮削器映射中的「删除」类关键词（如 1080p、高清）不在映射库中，插件完全不碰

## 文件说明

| 文件                   | 说明                                            |
| -------------------- | --------------------------------------------- |
| `tagMerge.yml`       | 插件定义（raw 任务插件）                                |
| `tagMerge.py`        | 合并逻辑：读映射库 → GraphQL 查询库内 tags → 逐组合并 + 补写别名   |
| `tag_merge_map.json` | 映射数据库（可手动编辑），由刮削器 `mapping_info.xml` 的关键词归组生成 |

## 注意事项

- 合并不可撤销，首次运行前请备份并预览 `tag_merge_map.json` 中将要生效的条目

- 映射库是静态文件，不随刮削器 `mapping_info.xml` 自动更新；如需刷新映射库请手动编辑或重新生成

- 日志中「跳过源 n 个」为正常现象：包括库内不存在的源名（映射库覆盖未来新增 tag）与已合并过的源
