# performerMerge

> v1.6.3：README 精简 — 删除使用方法逐步操作与技术细节，仅保留核心机制（匹配规则/短名清理/别名修复/合并行为）与注意事项

Stash 纯 UI 插件：遍历库内所有演员的名字和别名，归一化分组找出重名演员；每组选择目标演员后自动合并（保留目标的名字与图片，源演员的名字+别名原样并入目标别名、仅精确去重，其余字段按官方规则合并，场景/图库/图片/标签转移，源演员删除）。附带「短名清理」（删除被多人共享的单词短名别名）与「别名修复」（把合并成单行的错误别名条目拆回多个）。

## 依赖

- **Stash v0.31.0+**（依赖 `performerMerge` mutation，低版本会在面板中显示警告并禁用合并）
- 无需 Python、无需 API Key

## 安装

1. 将整个 `performerMerge` 文件夹复制到 Stash 插件目录（通常为 `~/.stash/plugins/` 或 Stash 数据目录下的 `plugins/`）
2. 重启 Stash
3. 导航栏右侧出现紫色合并图标即安装成功

## 触发方式

| 入口 | 行为 |
|---|---|
| 导航栏合并图标（紫色） | 面板：重名分组 / 短名清理 / 别名修复 / 强制合并 / 日志 |

## 匹配规则

| 步骤 | 说明 |
|---|---|
| 归一化 | NFC → 小写 → 全角括号转半角 → 去所有空白 → 片假名折叠为平假名（なな 与 ナナ 同名）；**保留** `(2)` 等消歧后缀（`An` 与 `An (2)` 不算重名） |
| 证据分级 | 四级证据按强度降序连组：① **stash_id**（同 endpoint + 同 id = 同一外部实体，硬证据无条件连组，可命中名字完全不同的同人）；② **共享 URL**（同一归一化 URL 恰好 2 人持有；≥3 人共享视为机构页不作证据）；③ **名字键**（主名 > 全名 > 单词短名；双方 disambiguation 互异 → 降为弱证据）。仅 ③ 的短名/降级连成的组挂「低可信度」徽章 |
| 常见名抑制 | 全库 ≥3 人共享的名字键（如 `Ai`、`AYAKA` 类短名）不参与连组 |
| 树级冲突检查 | ②③ 类边连组前检查两棵树**任意成员对**：同 endpoint 不同 stash_id 或同平台不同账号 URL → 拒绝该边，收入「强制合并」页人工复核（防传递链把冲突实体连进一组） |
| 组级冲突后验 | stash_id 硬证据无条件连组可能引入矛盾对 → 组内两两复检 ID/URL 冲突，命中挂「ID 冲突」「URL 冲突」徽章并退出「合并全部」 |
| URL 归一化 | 去协议/www/查询串/尾斜杠，统一小写；x.com / mobile.twitter.com 统一为 twitter；已知社交平台仅取账号段，博客/个人站保留完整路径 |
| 默认目标 | 场景数最多 → stash_id 数最多 → 创建最早 |

## 短名清理

不同刮削源常把罗马字/假名短名（`Ai`、`あい`）写进别名，这类名字常被多个**不同**演员共享，既是演员页噪音也是重名误报的主要来源（v1.0.2 起分组时已抑制，但别名仍留在库中）。

| 项 | 规则 |
|---|---|
| 清理对象 | 归一化后被 **≥2 个演员共享**（名字+别名都计数）的别名条目 |
| 短名判定 | 单词、无汉字、无符号（仅半角/全角罗马字、数字、假名，如 `Ai` / `あい` / `AYAKA` / `ゆずき`）；含空格或汉字的全名别名**不删** |
| 主名 | **永不删除**（仅操作 `alias_list`） |
| 提交方式 | 逐演员调用 `performerUpdate` 提交过滤后的完整别名列表，其余别名保持原顺序原样保留 |
| 逐键清理 | 每键独立「清理」（只处理该键）与「忽略」（收起误报卡，可恢复）；「清理全部」处理所有未忽略键，个别持有者提交失败时该键保留在列表中待重试 |
| 失败处理 | 个别演员剩余别名中存在历史遗留的仅大小写重复时，后端校验会拒绝该演员的更新 — 跳过并记日志，不中断批量 |

## 别名修复

某些操作会把演员的多个别名错误地保存成**一个条目**（如 `Ai, Mion Sonoda, Sonoda Mion, あい, 園田みおん`）。`alias_list` 是数组，损坏条目（元素含分隔符）归一化后是一整根巨串键，**既匹配不到任何人，也是重名分组的漏报源** — 拆分后片段才真正参与名字匹配。

| 项 | 规则 |
|---|---|
| 检测对象 | 别名条目含分隔符（半角 `,` / 全角 `，` / 顿号 `、`）且拆出 ≥2 个有效片段；尾部悬逗号（`Ai,`）属清尾修复。JAV/西文人名不含这些字符，无误拆风险 |
| 拆分规则 | 按分隔符拆分 → trim → 丢弃空段 → **丢弃与主名相同的片段**（后端校验会拒）→ 全局精确去重保序；未损坏的其余别名保持原顺序原样保留 |
| 提交方式 | 按演员聚合（一名演员可有多条损坏，一次提交），逐演员调用 `performerUpdate` 提交修复后的完整别名列表 |
| 快照语义 | 修复后的片段需**重新扫描**后才参与名字匹配（与短名清理一致）；拆出的短名片段会自然进入短名清理的视野（修复 → 重扫 → 清理） |
| 失败处理 | 个别演员提交失败时挂「失败」徽章保留待重试，不中断批量 |

## 合并行为

调用 Stash 原生 `performerMerge` mutation（`source` + `destination` + `values`），规则如下：

**声明规则（名字/图片/别名）**

- **名字/图片**：始终保留目标演员自己的 — 源演员名字不覆盖目标，源演员图片不继承（目标无图片时合并后也无图片）
- **别名**：源演员的名字 + 别名**全部原样写入**目标别名 — 不做任何归一化（NFC/小写/去空格/去括号后缀均不使用），仅按字符串**精确去重**；唯一例外是排除与目标名字**完全相同**的条目（与名字重复无信息量，且会导致后续编辑报错）。目标已有别名保持原顺序在前，源数据追加在后

**其余字段（对齐官方合并对话框默认值）**

- **消歧及单值字段**（生日、国籍、身高等）：目标为空时取第一个非空源值
- **stash_id**：按 endpoint 去重合并，目标已有 endpoint 时目标优先
- **URL / 标签**：并集；**自定义字段**：目标未定义的字段取第一个有值源
- **收藏/评分**：官方合并不处理，保留目标自己的值（源演员的值不保留）

**写入安全**

- **只提交变更字段**：列表字段（别名/stash_id/URL/标签）只在**变长**时提交且目标已有值全部保留在前（只增不减），单值字段只在「目标为空且源非空」时取值 — 任何字段都不会被写成空
- **未传字段不覆盖**：后端为部分更新语义（`hasField` 判定），JSON 中不存在的键不进变更集；不传 `name`/`image`，主名与图片不会被触碰
- **合并落库分两步**：先按变更集更新目标，再做纯关联表转移（场景/图库/图片/标签改挂目标，源演员删除），后端不写目标的任何数据列

**后端处理（`values` 之外）**

- 源演员的 **场景/图库/图片/标签** 引用转移到目标演员
- 源演员被 **删除**

## 注意事项

- 合并不可撤销（源演员被删除），批量合并前建议先逐组核对，或先在 Stash 自带合并对话框熟悉行为
- 扫描基于扫描时的数据快照；合并过程中若库结构被外部修改（如演员已被删除），该组会标记失败，重新扫描即可
- 名字匹配只做精确归一化匹配，不做模糊/读音匹配
- 别名按原样写入不做归一化去重：若结果中存在仅大小写不同的别名（如 `YUKI` 与 `yuki`），合并本身不会失败，但后续在官方 UI 编辑该演员的别名时会被校验拒绝（`performer contains duplicate alias`），需先手动清理
