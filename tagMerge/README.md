# tagMerge

> v2.1.0：查看映射页冲突兜底 — 工具栏「冲突项」筛选按钮（激活态白条指示）、冲突源标黄 + 红字明细、逐条「清理」按钮；搜索框清除按钮；修复宽屏编辑态保存/撤销按钮居左；映射库清理归一化重复源

Stash 纯 UI 插件：读取映射库，把库内名称相似的 tags（英文/日文/中文变体）合并为规范中文 tag。点击导航栏右侧的绿色标签图标打开面板，扫描后按分组预览将要合并的内容，逐组或一键全部合并。源 tag 名称合并后保留为目标的别名，场景/标记/图库/图片上的引用由 Stash 后端统一转移，数据不丢失。映射表可在「查看映射」分页内查看、搜索、编辑并导出文件，替换插件目录中的 `tag_merge_map.json` 生效。

## 依赖

- Stash v0.30+（`ui.assets` 资源路由，用于向面板提供 `tag_merge_map.json`；tagsMerge/tagCreate/tagUpdate 为老接口）

- 无需 Python，无需 requests

## 安装

1. 将整个 `tagMerge` 文件夹复制到 Stash 插件目录（通常为 Stash 数据目录下的 `plugins/`）
2. 重启 Stash，在「设置 → 插件」中确认 Tag Merge 已启用
3. 导航栏右侧出现绿色标签图标即安装成功

## 使用方法

1. **首次运行前建议先备份**：Stash「设置 → 任务 → 备份」（合并会删除源 tag，虽保留别名与引用，仍建议留底）
2. 点击导航栏右侧的绿色标签图标，打开面板（「分组 / 查看映射 / 日志」分页始终显示，无需先扫描）
3. 点击「开始扫描」— 每次扫描都会重新读取映射库（替换映射文件后无需重启，重新扫描即生效）
4. 在「分组」分页查看预览：组头即目标行（目标名 + 源计数；目标 tag 不存在时显示「新建」徽章），目标 tag 的引用计数徽章（场景/标记/图库/图片/演员/群组/工作室/别名，仅显示非零项）显示在「合并」按钮前；下方是源 tag 行（同名徽章显示在「忽略」按钮前，含「变体」标注表示按目标名的归一化变体匹配、未列入映射），鼠标指向行时高亮
5. 不想合并的内容有两级忽略，均仅本次会话有效（不写入任何数据，重新扫描即重置，误点可点「恢复」）：源行右侧「忽略」排除单个源（组内其他源仍可合并）；组头「合并」右侧的「忽略」折叠整组并从「合并全部」中排除。组头源计数、「可减少 tag」统计、确认框与实际执行均实时排除被忽略的源/组
6. 点击组内「合并」或顶部「合并全部」— 源 tag 删除，引用转移到目标，源名补写进目标别名；合并完成后该组折叠成一行（目标名 · 并入源数 + 「已合并」徽章，明细见日志）
7. 「日志」分页查看结果，每组一条：`目标 ← 合并 n 个源: 源1、源2…`

## 查看映射 / 编辑与导出

「查看映射」分页可直接维护映射表（映射数据始终以插件目录的 `tag_merge_map.json` 为唯一数据源）：

- 顶部黄框提示：编辑后需「导出文件」并手动替换插件目录中的同名文件 — 浏览器端 JS 无法直接写服务器文件，这是纯 UI 插件的固有限制
- 顶部一行：左侧搜索框（按目标名/源名实时过滤），右侧「添加」（新建映射，插入列表顶部进入编辑态）与「导出文件」（下载完整 JSON）；窄屏下条目头部的「N 源/编辑/删除」按钮与目标名同行显示（目标名超长时省略号截断，悬停可见全文）
- 每条映射可**编辑**（目标输入框 + 源名文本域，每行一个）、**保存**（应用到列表）、**撤销**（放弃本次修改）、**删除**（仅从映射表移除，不影响库内 tag）
- **重复校验**：编辑/添加时按归一化规则（全角→半角、忽略大小写与分隔符）实时检测目标重复、组内源重复、跨条目源重复、源名等于其他条目目标（防链式会跳过该源）；检出时输入框标红边并显示红色提示文案。重复不强制阻断 — 单条保存时弹确认可继续，也可选择继续编辑或删除该条
- **冲突兜底**：列表态下，归一化重复/跨条目重复/与其他条目目标重名的源词条标黄，并以红字提示重复明细（目标重复 · 组内源重复 · 源与其他条目重复 · 源与其他目标重复；与本组目标归一化相同的源是目标自身写法变体，正常并入，不算冲突）；存在冲突时工具栏显示「冲突项」按钮 — 点击进入筛选视图（下方只列出含冲突源的条目，激活态按钮底部有白色指示条），冲突条目「编辑」按钮左侧出现「清理」按钮，一键移除该条目的冲突源（组内归一化重复保留首个；跨条目重复本条目让出，留谁由你逐条决定；与其他条目目标重名直接移除）；清理后条目自动移出筛选，全部清理完自动退出筛选
- 「导出文件」下载包含 `_` 开头说明键的完整 JSON（`tag_merge_map.json`），替换插件目录中的同名文件后**重新扫描生效**
- 面板内编辑内容刷新页面即丢失 — 修改后请及时导出；状态行分色提示：「● 已编辑未导出」黄字，导出成功绿字、失败红字

映射库当前覆盖：395 个目标 / 2659 个源名称（v2.0.0 设计时为 365/2285，先后按刮削器 `mapping_info.xml` 与库内真实英文 tag 补充，并清理归一化后的重复源与跨条目冲突）；对当前库的全量模拟结果：合并 261 组 / 617 个源 tag（含目标自身的写法变体）、新建 77 个目标、库内 tag 由 1470 精简至 930。

## 映射库格式

`tag_merge_map.json` 为纯 JSON，可手动编辑或在「查看映射」分页编辑后导出替换（面板经 `/plugin/tagMerge/assets/` 路由实时读取）：

```json
{
  "_说明": "以 _ 开头的键会被忽略",
  "3P/4P": ["3P·4P", "3P、4P", "3p", "4P", "4p", "３P"],
  "口枷": ["ボールギャグ", "口球", "球形口塞"],
  "出轨/NTR": ["NTR", "不倫", "寝取り・寝取られ"]
}
```

- **键** = 合并目标 tag 名（目标不存在时执行中自动新建）

- **值** = 源 tag 名列表（合并进目标并保留为别名）

- 以 `_` 开头的键被忽略 — 想临时禁用某条规则，把目标名加 `_` 前缀即可

- 源名匹配为**归一化后精确匹配**：全角→半角（`３P`→`3P`）、不区分大小写、忽略全/半角空格及 `·、，/` 等分隔符；不做子串或模糊匹配

## 合并行为

调用 Stash 原生 `tagsMerge`（与官方「合并」对话框一致）：

1. 源 tag 的**场景/标记/图库/图片**等引用转移到目标（后端处理）
2. 源 tag 被删除，其名称由插件补写进目标的**别名**（幂等去重，仍可通过别名搜索）
3. 目标不存在时自动 `tagCreate` 新建（确认该组有有效源后才创建，避免产生空 tag）

## 安全机制

- **幂等**：已合并/不存在的源自动跳过，可安全重复执行；重新扫描即刷新预览

- **两级忽略**：预览中可按源或按组忽略——源级「忽略」跳过单个源（映射表某条与库内语义不符时的安全网），组级「忽略」折叠整组并退出「合并全部」队列；均仅单次会话有效，不写入任何持久状态，重新扫描重置

- **防链式**：某组的目标名不会成为其他组的源，避免 A→B、B→C 连环合并；组内提示行会显示被跳过的链式源名数量

- **编辑器重复校验**：查看映射分页实时检测归一化后的目标/源重复（红色提示 + 保存前确认），防止一个源名同时指向两个目标等配置错误

- **无删除操作**：只做合并，刮削器映射中的「删除」类关键词（如 1080p、高清）不在映射库中，插件完全不碰

## 文件说明

| 文件                   | 说明                                            |
| -------------------- | --------------------------------------------- |
| `tagMerge.yml`       | 插件定义（纯 UI 插件，assets 把插件目录挂载到 `/plugin/tagMerge/assets/`） |
| `tagMerge.js`        | 面板逻辑：读映射库 → 扫描库内 tags → 分组预览 → 逐组/批量合并 + 补写别名 + 映射表编辑器 |
| `tagMerge.css`       | 面板样式（tgm- 前缀，绿色主题）                            |
| `tag_merge_map.json` | 映射数据库（初始版本，可在面板编辑或手动修改），由刮削器 `mapping_info.xml` 的关键词归组生成 |

## 注意事项

- 合并不可撤销，首次运行前请备份并预览 `tag_merge_map.json` 中将要生效的条目

- 映射库是静态文件，不随刮削器 `mapping_info.xml` 自动更新；如需刷新映射库请手动编辑或重新生成

- 分组卡片中的「未匹配 N 个源名」为正常现象：包括库内不存在的源名（映射库覆盖未来新增 tag）与已合并过的源
