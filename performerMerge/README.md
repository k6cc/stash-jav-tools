# performerMerge

> v1.6.0：分组引擎重写为**证据分级连组**（stash_id 硬证据 → 共享 URL → 主名/全名匹配 → 短名/消歧互异降级，按强度降序处理保证确定性）；名字/URL 边连组前执行**树级冲突检查**（两棵树任意成员对存在同端点不同 stash_id 或同平台不同账号 → 拒绝连组送「强制合并」页），杜绝传递链把冲突实体并进一组；新增 **URL 归一化与冲突检测**（x.com/mobile.twitter.com 统一为 twitter，已知社交平台仅取账号段），成员行新增 **URL 数量徽章**（组内同平台不同账号时标黄）；组级新增琥珀「ID 冲突」「URL 冲突」徽章（冲突组退出「合并全部」）与透明框「低可信度」徽章（仅弱证据连组）；假名折叠（片假名↔平假名同名互通，なな 与 ナナ）；「强制合并」页同时接收 URL 冲突阻断对，文案更新为 ID/URL 冲突；新增**「别名修复」**标签页（把合并成单行的错误别名条目拆回多个，详见下方专节）

Stash 纯 UI 插件：遍历库内所有演员的名字和别名，归一化分组找出重名演员；每组选择一个目标演员后，其余演员自动合并进来（合并后保留目标的名字与图片，源演员的名字+别名原样并入目标别名、仅精确去重，其余字段按官方规则合并；场景/图库/图片/标签转移，源演员删除）。附带「短名清理」（删除被多人共享的单词短名别名）与「别名修复」（把合并成单行的错误别名条目拆回多个）功能。

## 依赖

- **Stash v0.31.0+**（依赖 `performerMerge` mutation，低版本会在面板中显示警告并禁用合并按钮）

- 无需 Python、无需 API Key

## 安装

1. 将整个 `performerMerge` 文件夹复制到 Stash 插件目录（通常为 `~/.stash/plugins/` 或 Stash 数据目录下的 `plugins/`）
2. 重启 Stash
3. 导航栏右侧出现紫色合并图标按钮

## 使用方法

1. 点击导航栏右侧的 **合并图标**（紫色）打开面板
2. 点击 **开始扫描** — 分页拉取全部演员（名字+别名+URL），归一化后按证据分级并查集分组
3. 在「重名分组」标签页查看结果：

   - 每行一个演员：单选框选择 **目标**（默认预选场景数最多、stash\_id 最多、创建最早的演员）

   - 行内徽章显示场景/图库/图片/别名/URL 数量（URL 冲突标黄）、stash\_id 来源站点（冲突端点标琥珀）、收藏与评分；组头部按扫描后验挂「ID 冲突」「URL 冲突」琥珀徽章或「低可信度」透明框徽章（悬浮显示明细）
4. 点击组内 **合并** 按钮合并该组（有确认提示；冲突组确认框额外警示请逐对核实）；**忽略** 按钮将误报组收缩成一行灰色（可随时 **恢复**），**合并全部** 自动跳过忽略的组与冲突组
5. 扫描完成后出现 **「短名清理」** 标签页（短名清单来自同一扫描；括号内为扫描到的共享短名总数，忽略不减少）：顶部搜索框输入即过滤短名/演员名（选中态主题色边框，右对齐 × 清除并同步清空输入框），预览后点击 **清理全部** 批量处理，或点击单个短名卡的 **清理** 只处理该键（均有确认提示，规则见按钮悬浮提示）；误报短名卡可 **忽略** 收起（可恢复），清理全部自动跳过。清理在当前页进行（不跳转日志），完成的卡片**收缩变灰**标注「已清理」，不自动重扫 — 分组页是清理前快照，需要时手动重扫即可
6. **「别名修复」** 标签页（括号内为扫描到的损坏演员总数，忽略不减少）：列出别名单行合并错误的演员（按演员聚合，一名演员可有多条损坏）。每条损坏显示原始串（粉色）与拆分预览（片段徽章），点击 **修复**（主题色，改写语义非删除）拆回多个别名并提交完整别名列表，或 **修复全部** 批量处理（均有确认提示）；误报卡可 **忽略** 收起（可恢复）。规则详见下方专节
7. **「强制合并」** 标签页（括号内为扫描到的冲突对总数，忽略不减少）：列出被 ID/URL 冲突阻断的重名对。卡片头部按冲突类型挂琥珀色 **「ID 冲突」「URL 冲突」** 徽章（悬浮显示冲突明细：端点 stash\_id / 平台账号），成员行中冲突端点的 stash\_id 徽章标琥珀色、URL 冲突徽章标黄色；卡片与重名分组同款（单选框选目标，悬浮提示查看组内重名与 URL 冲突），误报对可 **忽略** 收起（可恢复）。**强制合并** 按钮（红色）逐对手动合并（确认框提示被冲突证据阻断、请核实是同一人后再继续；冲突明细可悬浮徽章查看）。该页**纯手动**，不参与「合并全部」与统计区计数
8. 「日志」标签页查看合并/清理/修复过程与结果

## 短名清理

不同刮削源常把罗马字短名（`Ai`、`Ayaka`、`Saori`）或假名短名（`あい`、`ゆずき`）写进别名，这类名字往往被多个**不同**演员共享，既在演员详情页产生噪音，也是重名误报的主要来源（v1.0.2 起分组时已抑制，但别名仍留在库中）。

| 项             | 规则                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| 清理对象         | 归一化后被 **≥2 个演员共享**（名字+别名都计数）的别名条目                                                          |
| 短名判定         | 单词、无汉字、无符号：仅半角/全角罗马字、数字、假名（`Ai` / `あい` / `AYAKA` / `ゆずき`）；含空格（`Iroha Suzumura`）或汉字（`兒玉七海`）的全名别名**不删** |
| 主名           | **永不删除**（仅操作 `alias_list`）                                                                              |
| 提交方式         | 逐演员调用 `performerUpdate` 提交过滤后的完整别名列表，其余别名保持原顺序原样保留；完成后不自动重扫，已清理卡片收缩变灰（标签页计数为扫描到的总数，忽略不减少）                                        |
| 逐键清理         | 每个短名卡有独立 **清理** 按钮（红色，删除语义，只处理该键）与 **忽略** 按钮（灰色，收起误报卡，可恢复）；**清理全部** 处理所有未忽略键。个别持有者提交失败时该键保留在列表中待重试                                      |
| 持有者展示       | 每行显示：演员名 + 待删短名（粉色）+ ID；下方暗色小字显示该演员的**其他别名**（清理后自动消失的仅是粉色项）                                                    |
| 搜索过滤         | 顶部搜索框**输入即过滤**（无需回车，中文输入法组合中不触发），匹配短名原始串或持有者名字；右对齐 **×** 按钮清除（仅输入非空时显示）                                                  |
| 对刮削的影响       | 按番号刮削返回的是全名，演员匹配不受影响；纯短名连接的重名分组（多为不同人）在清理后消失，仅剩 stash\_id 硬证据与全名匹配的分组                              |
| 失败处理         | 个别演员剩余别名中存在历史遗留的仅大小写重复时，后端校验会拒绝该演员的更新 — 跳过并记日志，不中断批量                                                 |

## 别名修复

某些操作会把演员的多个别名错误地保存成**一个条目**（如 `Ai, Mion Sonoda, Sonoda Mion, あい, 園田みおん`）。Stash 的 `alias_list` 是数组，损坏条目在数据层一眼可辨（元素含分隔符），但演员页把数组渲染成 `, ` 连接，肉眼分不出。这类条目归一化后是一整根巨串键，**既匹配不到任何人，也是重名分组的漏报源** — 拆分后片段才真正参与名字匹配。

| 项             | 规则                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| 检测对象         | 别名条目含分隔符（半角 `,` / 全角 `，` / 顿号 `、`）且拆出 ≥2 个有效片段；尾部悬逗号（`Ai,`）属清尾修复。JAV/西文人名不含这些字符，无误拆风险 |
| 拆分规则         | 按分隔符拆分 → trim → 丢弃空段 → **丢弃与主名相同的片段**（后端校验会拒）→ 全局精确去重保序；未损坏的其余别名保持原顺序原样保留 |
| 提交方式         | 按演员聚合（一名演员可有多条损坏，一次提交），逐演员调用 `performerUpdate` 提交修复后的完整别名列表；完成后卡片收缩变灰，不自动重扫 |
| 展示           | 每条损坏显示原始串（粉色）与拆分预览（片段徽章）；搜索框输入即过滤演员名/别名内容 |
| 快照语义         | 修复后的片段需**重新扫描**后才参与名字匹配（与短名清理一致）；拆出的短名片段（如 `Ai`）会自然进入短名清理的视野（修复 → 重扫 → 清理） |
| 失败处理         | 个别演员提交失败时卡片挂「失败」徽章保留待重试，不中断批量；修复全部自动跳过已修复/已忽略项 |

## 匹配规则

| 步骤           | 说明                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 归一化          | NFC → 小写 → 全角括号转半角 → 去所有空白 → 片假名折叠为平假名（なな 与 ナナ 同名）；**保留** `(2)` 等消歧后缀（后缀代表同名不同人，`An` 与 `An (2)` 不算重名）                                                                    |
| 证据分级         | 四级证据按强度降序连组，保证确定性：① **stash\_id**（同 endpoint + 同 id = 同一外部实体，硬证据无条件连组，可命中名字完全不同的同人，如罗马音 vs 日文名）；② **共享 URL**（同一归一化 URL 恰好 2 人持有；≥3 人共享视为机构页不作证据）；③ **名字键**（主名匹配 > 全名匹配 > 单词短名；双方 disambiguation 互异 → 降为弱证据）；仅 ③ 的短名/降级连成的组挂「低可信度」徽章 |
| 常见名抑制       | 全库 ≥3 人共享的名字键（如 `Ai`、`AYAKA` 类短名）不参与连组；仅按 stash\_id 匹配的组头部显示「stash\_id 匹配」徽章                                     |
| 树级冲突检查     | ②③ 类边连组前检查两棵树**任意成员对**：同 endpoint 不同 stash\_id 或同平台不同账号 URL → 拒绝该边，收入「强制合并」页人工复核（防止传递链把冲突实体连进一组） |
| 组级冲突后验     | stash\_id 硬证据无条件连组可能引入矛盾对 → 组内两两复检 ID/URL 冲突，命中挂「ID 冲突」「URL 冲突」徽章并退出「合并全部」 |
| URL 归一化     | 去协议/www/查询串/尾斜杠，统一小写；x.com / mobile.twitter.com 统一为 twitter；已知社交平台仅取账号段（兼容推文链接），博客/个人站保留完整路径 |
| 默认目标         | 场景数最多 → stash\_id 数最多 → 创建最早                                                                                                                     |

**核对分组**：悬停任意成员行，tooltip 中「组内重名」列出该演员与组内其他成员共享的名字/别名，「同 stash\_id」列出共享的外部实体 ID，「URL 冲突」列出冲突平台，可据此判断分组是否合理；行内 URL 徽章显示数量（冲突标黄），组头部冲突徽章悬浮显示明细（端点 stash\_id / 平台账号）。

**注意**：链式别名连组已被树级冲突检查约束（传递链上任一冲突对都会阻断该边），未被阻断的链式组仍建议核对；stash\_id 组证据最硬，但名字差异大时目标选择要谨慎（合并后名字/图片保留目标，源名字进别名）。3 人以上同名在 JAV 库中多为不同人，会被常见名抑制规则跳过——若确为同人重复，通常会先经 stash\_id 信号命中。

## 合并行为

调用 Stash 原生 `performerMerge` mutation（`source` + `destination` + `values`），合并规则如下：

**声明规则（名字/图片/别名）**

1. **名字/图片**：始终保留目标演员自己的 — 源演员名字不覆盖目标，源演员图片不继承（目标无图片时合并后也无图片）
2. **别名**：源演员的名字 + 别名**全部原样写入**目标别名 — 不做任何归一化（NFC/小写/去空格/去括号后缀均不使用），仅按字符串**精确去重**；唯一例外是排除与目标名字**完全相同**的条目（与名字重复无信息量，且会导致后续编辑报错）。目标已有别名保持原顺序在前，源数据追加在后

**其余字段（对齐官方合并对话框默认值）**

- **消歧及单值字段**（生日、国籍、身高等）：目标为空时取第一个非空源值

- **stash\_id**：按 endpoint 去重合并，目标已有 endpoint 时目标优先

- **URL / 标签**：并集

- **自定义字段**：目标未定义的字段取第一个有值源

- **收藏/评分**：官方合并不处理，保留目标自己的值（源演员的值不保留）

**写入安全**

- **只提交变更字段**：`values` 仅包含实际需要变化的键；列表字段（别名/stash\_id/URL/标签）只在**变长**时提交且目标已有值全部保留在前（只增不减），单值字段只在「目标为空且源非空」时取值 — 任何字段都不会被写成空
- **未传字段不覆盖**：后端 `performerMerge`/`performerUpdate` 为部分更新语义（`hasField` 判定），JSON 中不存在的键不进变更集，目标已有值原样保留；不传 `name`/`image`，主名与图片不会被触碰
- **合并落库分两步**：先按变更集更新目标，再做纯关联表转移（场景/图库/图片/标签改挂目标，源演员删除），后端不写目标的任何数据列

**后端处理（`values`** **之外）**

- 源演员的 **场景/图库/图片/标签** 引用转移到目标演员

- 源演员被 **删除**

## 技术细节

- **幂等保护**：`window.__pdmLoaded` 防止重复加载

- **i18n bridge**：通过 `PluginApi.patch.before("App")` 注入 IntlProvider，支持中英文

- **DOM 注入**：导航栏按钮注入位置与 JavStashLinker 一致（`.navbar-buttons` 右侧区），History 劫持 + MutationObserver 保证 SPA 导航后按钮存在

- **弹窗样式**：复用 JavStashLinker 面板风格（`pdm-` 前缀，紫色 `#7048e8` 主题）；面板内部滚动 + 矮内容上下居中，≤480px 两侧铺满，小按钮/badge 统一 22px 等高基座，符合仓库 UI 交互设计规范

- **分块渲染**：分组列表按 50 条分块 + IntersectionObserver 懒加载，万级演员不卡顿

- **就地更新**：切换目标演员只更新行高亮与「目标」徽章，不整页重渲染，滚动位置不丢失

- **忽略状态**：分组/冲突对/修复项按各自 key、短名按归一化键记录（`ignored` / `snIgnored` / `arIgnored`），**跨扫描持久**（重扫后仍保持忽略，可随时恢复）；忽略项收缩为仅头部一行、不计入待处理统计，`合并全部`/`清理全部`/`修复全部` 自动跳过（强制合并本就不参与批量）

- **短名搜索**：短名清理页搜索框 `oninput` 即时过滤（IME 组合中经 `isComposing` + `compositionend` 处理，拼音输入不误触发），只就地重建列表容器（disconnect 旧 IntersectionObserver），输入框焦点与光标不丢失；搜索行/过滤逻辑与别名修复/强制合并页共用

- **强制合并页**：被 ID/URL 冲突阻断的名字/URL 对按演员对聚合（同一对可含多条被阻断边），对结构（pair）与分组（group）同构，复用目标选择/合并提交/成员行渲染；已通过其他证据连成组的对不重复收录（组级冲突在重名分组页以徽章标示）；确认框仅提示冲突性质与核实要求（明细通过徽章悬浮提示查看）；合并后源演员若仍出现在其他待处理分组/冲突对中会记日志提醒重扫；该页纯手动，不参与「合并全部」与统计区计数

- **统计口径**：统计区「待合并组/可减少演员/涉及演员」均只统计**待合并**组（排除已合并/已忽略/冲突阻断），忽略一组统计区立即同步；「已合并组」单独统计；标签页「重名分组 (N)」「短名清理 (N)」「别名修复 (N)」「强制合并 (N)」均为**扫描到的全量**（含已合并/已忽略/已清理/已修复，忽略不改变计数），已处理态在页面内有卡片状态与文案兜底

- **端点品牌名**：stash\_id 徽章/悬浮提示中已知 Stash-box 端点显示品牌名（`theporndb.net`→ThePornDB、`stashdb.org`→StashDB、`javstash.org`→JAVStash），未知端点显示 host

- **悬浮提示**：演员行使用自定义 tooltip（非原生 `title`）— 条目分行、条目头加粗、长别名自动换行，跟随光标并自动避开屏幕边缘；触屏设备（无 hover）不启用

- **版本检查**：面板打开时查询 `version { version }`，低于 v0.31.0 显示警告并禁用合并

## 注意事项

- 合并不可撤销（源演员被删除），批量合并前建议先逐组核对，或先在 Stash 自带合并对话框熟悉行为

- 扫描基于扫描时的数据快照；合并过程中若库结构被外部修改（如演员已被删除），该组会标记失败，重新扫描即可

- 名字匹配只做精确归一化匹配，不做模糊/读音匹配

- 别名按原样写入不做归一化去重：若结果中存在仅大小写不同的别名（如 `YUKI` 与 `yuki`，或与名字仅大小写不同的别名），合并本身不会失败（后端 merge 路径不做别名校验），但后续在官方 UI 编辑该演员的别名时会被校验拒绝（`performer contains duplicate alias`），需先手动清理这些条目
