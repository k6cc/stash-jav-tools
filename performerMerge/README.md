# performerMerge

> v1.1.0：新增「短名清理」— 扫描后自动找出被 ≥2 人共享的单词短名别名（如 `Ai`/`あい`/`Ayaka`，无空格无汉字的纯罗马字/假名），预览确认后一键从所有持有者删除（主名与含空格/汉字的全名别名不受影响），也支持单个短名单独清理，完成卡片收缩变灰、日志记录具体短名；演员行悬浮提示改为条目分行显示（条目头加粗）；修复切换标签页时弹窗轻微位移；同时包含 v1.0.2 分组修复（常见名抑制 + 同 endpoint stash\_id 冲突阻断，根治 167 人超大误报组）

Stash 纯 UI 插件：遍历库内所有演员的名字和别名，归一化分组找出重名演员；每组选择一个目标演员后，其余演员自动合并进来（合并后保留目标的名字与图片，源演员的名字+别名原样并入目标别名、仅精确去重，其余字段按官方规则合并；场景/图库/图片/标签转移，源演员删除）。附带「短名清理」功能，一键删除被多人共享的单词短名别名。

## 依赖

- **Stash v0.31.0+**（依赖 `performerMerge` mutation，低版本会在面板中显示警告并禁用合并按钮）

- 无需 Python、无需 API Key

## 安装

1. 将整个 `performerMerge` 文件夹复制到 Stash 插件目录（通常为 `~/.stash/plugins/` 或 Stash 数据目录下的 `plugins/`）
2. 重启 Stash
3. 导航栏右侧出现紫色合并图标按钮

## 使用方法

1. 点击导航栏右侧的 **合并图标**（紫色）打开面板
2. 点击 **开始扫描** — 分页拉取全部演员（名字+别名），归一化后按并查集分组
3. 在「重名分组」标签页查看结果：

   - 每组头部显示共享名称（被 ≥2 个成员使用的名字/别名）和人数

   - 每行一个演员：单选框选择 **目标**（默认预选场景数最多、stash\_id 最多、创建最早的演员）

   - 行内徽章显示场景/图库/图片/别名数量、stash\_id 来源站点、收藏与评分
4. 点击组内 **合并** 按钮（有确认提示），或点击顶部 **合并全部** 批量处理
5. 扫描完成后出现 **「短名清理」** 标签页（括号内为待清理短名数，`0` 表示无需清理；详见下节）：预览后点击 **清理全部** 批量处理，或点击单个短名卡的 **清理** 只处理该键（均有确认提示，规则见按钮悬浮提示）。清理在当前页进行（不跳转日志），完成的卡片**收缩变灰**标注「已清理」，不自动重扫 — 分组页是清理前快照，需要时手动重扫即可
6. 「日志」标签页查看合并/清理过程与结果

## 短名清理

不同刮削源常把罗马字短名（`Ai`、`Ayaka`、`Saori`）或假名短名（`あい`、`ゆずき`）写进别名，这类名字往往被多个**不同**演员共享，既在演员详情页产生噪音，也是重名误报的主要来源（v1.0.2 起分组时已抑制，但别名仍留在库中）。

| 项             | 规则                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| 清理对象         | 归一化后被 **≥2 个演员共享**（名字+别名都计数）的别名条目                                                          |
| 短名判定         | 单词、无汉字、无符号：仅半角/全角罗马字、数字、假名（`Ai` / `あい` / `AYAKA` / `ゆずき`）；含空格（`Iroha Suzumura`）或汉字（`兒玉七海`）的全名别名**不删** |
| 主名           | **永不删除**（仅操作 `alias_list`）                                                                              |
| 提交方式         | 逐演员调用 `performerUpdate` 提交过滤后的完整别名列表，其余别名保持原顺序原样保留；完成后不自动重扫，已清理卡片收缩变灰（标签页计数只含待清理键）                                        |
| 逐键清理         | 每个短名卡有独立 **清理** 按钮（红色，删除语义），只处理该键；**清理全部** 处理所有键。个别持有者提交失败时该键保留在列表中待重试                                      |
| 持有者展示       | 每行显示：演员名 + 待删短名（粉色）+ ID；下方暗色小字显示该演员的**其他别名**（清理后自动消失的仅是粉色项）                                                    |
| 对刮削的影响       | 按番号刮削返回的是全名，演员匹配不受影响；纯短名连接的重名分组（多为不同人）在清理后消失，仅剩 stash\_id 硬证据与全名匹配的分组                              |
| 失败处理         | 个别演员剩余别名中存在历史遗留的仅大小写重复时，后端校验会拒绝该演员的更新 — 跳过并记日志，不中断批量                                                 |

## 匹配规则

| 步骤           | 说明                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 归一化          | NFC → 小写 → 全角括号转半角 → 去所有空白；**保留** `(2)` 等消歧后缀（后缀代表同名不同人，`An` 与 `An (2)` 不算重名）                                                                    |
| stash\_id 信号 | 同 endpoint + 同 stash\_id = 同一外部实体（硬证据，无条件连组），可命中名字完全不同的同人（如罗马音 vs 日文名）；仅按 stash\_id 匹配的组头部显示「stash\_id 匹配」徽章                                     |
| 名字信号         | 名字和别名都作为键，但需通过两层过滤：① **常见名抑制** — 全库 ≥3 人共享的键（如 `Ai`、`AYAKA` 类短名）不参与连组；② **冲突阻断** — 两人在同一 endpoint 持有不同 stash\_id（策展库判定为不同人）时名字匹配作废。通过后经并查集传递闭合成组 |
| 默认目标         | 场景数最多 → stash\_id 数最多 → 创建最早                                                                                                                     |

**核对分组**：悬停任意成员行，tooltip 中「组内重名」列出该演员与组内其他成员共享的名字/别名，「同 stash\_id」列出共享的外部实体 ID，可据此判断分组是否合理。

**注意**：链式别名仍可能把不同演员连进一组（A~~B、B~~C 各共享不同罕见别名 → 三人一组），这类组人数通常 ≤3，合并前请核对；stash\_id 组证据最硬，但名字差异大时目标选择要谨慎（合并后名字/图片保留目标，源名字进别名）。3 人以上同名在 JAV 库中多为不同人，会被常见名抑制规则跳过——若确为同人重复，通常会先经 stash\_id 信号命中。

## 合并行为

调用 Stash 原生 `performerMerge` mutation（`source` + `destination` + `values`），合并规则如下：

**声明规则（名字/图片/别名）**

1. **名字/图片**：始终保留目标演员自己的 — 源演员名字不覆盖目标，源演员图片不继承（目标无图片时合并后也无图片）
2. **别名**：源演员的名字 + 别名**全部原样写入**目标别名 — 不做任何归一化（NFC/小写/去空格/去括号后缀均不使用），仅按字符串**精确去重**；唯一例外是排除与目标名字**完全相同**的条目（与名字重复无信息量，且会导致后续编辑报错）。目标已有别名保持原顺序在前，源数据追加在后

**其余字段（对齐官方合并对话框默认值）**

- **消歧及单值字段**（生日、国籍、身高等）：目标为空时取第一个非空源值

- **stash\_id**：按 endpoint 去重合并，目标已有 endpoint 时目标优先

- **URL / 标签**：并集

- **自定义字段**：目标未定义的字段取第一个有值源

- **收藏/评分**：官方合并不处理，保留目标自己的值（源演员的值不保留）

**写入安全**

- **只提交变更字段**：`values` 仅包含实际需要变化的键；列表字段（别名/stash\_id/URL/标签）只在**变长**时提交且目标已有值全部保留在前（只增不减），单值字段只在「目标为空且源非空」时取值 — 任何字段都不会被写成空
- **未传字段不覆盖**：后端 `performerMerge`/`performerUpdate` 为部分更新语义（`hasField` 判定），JSON 中不存在的键不进变更集，目标已有值原样保留；不传 `name`/`image`，主名与图片不会被触碰
- **合并落库分两步**：先按变更集更新目标，再做纯关联表转移（场景/图库/图片/标签改挂目标，源演员删除），后端不写目标的任何数据列

**后端处理（`values`** **之外）**

- 源演员的 **场景/图库/图片/标签** 引用转移到目标演员

- 源演员被 **删除**

## 技术细节

- **幂等保护**：`window.__pdmLoaded` 防止重复加载

- **i18n bridge**：通过 `PluginApi.patch.before("App")` 注入 IntlProvider，支持中英文

- **DOM 注入**：导航栏按钮注入位置与 JavStashLinker 一致（`.navbar-buttons` 右侧区），History 劫持 + MutationObserver 保证 SPA 导航后按钮存在

- **弹窗样式**：复用 JavStashLinker 面板风格（`pdm-` 前缀，紫色 `#7048e8` 主题）

- **分块渲染**：分组列表按 50 条分块 + IntersectionObserver 懒加载，万级演员不卡顿

- **就地更新**：切换目标演员只更新行高亮与「目标」徽章，不整页重渲染，滚动位置不丢失

- **端点品牌名**：stash\_id 徽章/悬浮提示中已知 Stash-box 端点显示品牌名（`theporndb.net`→ThePornDB、`stashdb.org`→StashDB、`javstash.org`→JAVStash），未知端点显示 host

- **悬浮提示**：演员行使用自定义 tooltip（非原生 `title`）— 条目分行、条目头加粗、长别名自动换行，跟随光标并自动避开屏幕边缘；触屏设备（无 hover）不启用

- **版本检查**：面板打开时查询 `version { version }`，低于 v0.31.0 显示警告并禁用合并

## 注意事项

- 合并不可撤销（源演员被删除），批量合并前建议先逐组核对，或先在 Stash 自带合并对话框熟悉行为

- 扫描基于扫描时的数据快照；合并过程中若库结构被外部修改（如演员已被删除），该组会标记失败，重新扫描即可

- 名字匹配只做精确归一化匹配，不做模糊/读音匹配

- 别名按原样写入不做归一化去重：若结果中存在仅大小写不同的别名（如 `YUKI` 与 `yuki`，或与名字仅大小写不同的别名），合并本身不会失败（后端 merge 路径不做别名校验），但后续在官方 UI 编辑该演员的别名时会被校验拒绝（`performer contains duplicate alias`），需先手动清理这些条目
